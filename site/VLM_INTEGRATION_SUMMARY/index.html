    Key Design Decisions¶

    1. Leverage DIMOS Infrastructure - Don't rebuild what exists
    2. Use dimos.models.qwen.video_query.query_single_frame() for scene understanding
    3. Use dimos.models.qwen.video_query.get_bbox_from_qwen_frame() for object detection

    4. Benefit from production-ready VLM integration

    5. Skills-Based Architecture - Flexible, testable, reusable

    6. Each skill is independent and testable
    7. Works with any agent (not tied to DIMOS agent architecture)

    8. Returns structured SkillResult dataclass

    9. Optional DIMOS Dependency - Graceful degradation

    10. SnapshotSkill works without DIMOS (PIL/numpy only)
    11. VLM skills require DIMOS but fail gracefully

    12. require_dimos flag in VisionSkillBase

    13. Cost-Effective - Qwen over GPT-4V

    14. Qwen: ~$0.001-0.003 per image
    15. GPT-4V: ~$0.005-0.015 per image
    16. 2-5x cost savings for routine vision tasks

    Architecture¶

    Class Hierarchy¶

    VisionSkillBase (base class)
├── __init__(image_dir, require_dimos)
├── _save_image(image, prefix) → Path
├── _numpy_to_pil(image) → Image.Image
│
├── SnapshotSkill (require_dimos=False)
│   └── execute(image, **kwargs) → SkillResult
│
├── DescribeSceneSkill (require_dimos=True)
│   └── execute(image, query, save_image) → SkillResult
│
├── LocateObjectSkill (require_dimos=True)
│   └── execute(image, object_name, save_image) → SkillResult
│
└── DetectObjectsSkill (require_dimos=True)
    └── execute(image, save_image) → SkillResult

    SkillResult Data Structure¶

    @dataclass
class SkillResult:
    success: bool                      # Did the skill succeed?
    data: Optional[Dict[str, Any]]     # Skill output (image_path, description, bbox, etc.)
    error: Optional[str]               # Error message if failed
    telemetry: Optional[Dict[str, Any]] # Performance metrics (size, duration, etc.)

    Lessons Learned¶

    1. Don't Rebuild Existing Infrastructure
    2. DIMOS already had production-ready Qwen integration
    3. Saved ~2-3 days of development time

    4. Better maintenance (upstream improvements)

    5. Skills-Based Architecture is Flexible

    6. Works with any agent system
    7. Easy to test independently

    8. Can be called from multiple contexts

    9. Graceful Degradation Matters

    10. SnapshotSkill works without DIMOS
    11. VLM skills skip gracefully without API key

    12. Better user experience during development

    13. Documentation While Building

    14. Created DIMOS_VISION_CAPABILITIES.md during discovery
    15. README.md with implementation
    16. Easier to remember context and decisions
